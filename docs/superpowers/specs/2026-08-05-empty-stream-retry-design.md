# 空流错误自动重试设计

日期：2026-08-05  
状态：已确认并实施

## 背景

连续翻译大量字幕时，模型服务可能偶发返回空的或提前结束的流式响应。当前 AI SDK 会抛出 `NoOutputGeneratedError`，错误信息通常为：

```text
No output generated. Check the stream for errors.
```

程序虽然已有最多三次的自动重试机制，但当前只识别 `NoObjectGeneratedError`，没有将 `NoOutputGeneratedError` 认定为可重试错误，因此第一次遇到空流就会停止当前字幕任务。用户手动重试后能够成功，说明这类错误通常是临时的服务或连接异常。

## 目标

1. 将 AI SDK 的 `NoOutputGeneratedError` 纳入现有最多三次自动重试。
2. 仅重试当前失败的请求和字幕批次，不清除已经完成的翻译进度。
3. 每次重试继续经过现有 RPM 限制器，不绕过请求频率约束。
4. 三次均未生成输出时，才将当前任务标记为失败。
5. 鉴权、无效 API 地址、模型不存在等确定性错误仍立即失败。
6. 肉眼相同的外层错误和内部原因只显示一次。

## 重试范围

以下错误继续或新增为可重试：

- `NoOutputGeneratedError`；
- 现有的 `NoObjectGeneratedError`；
- HTTP 429；
- HTTP 5xx；
- AI SDK 标记为可重试的 API 错误；
- 现有的网络中断、超时和不完整模型输出错误。

以下错误不应因为本次修改而重试：

- HTTP 400、401、403、404；
- API Key 为空或无效；
- API 地址无效或不符合安全规则；
- 模型名称不存在且服务商明确返回客户端错误；
- 字幕格式、编码、checkpoint 或输出路径错误；
- 用户主动取消任务；
- SSA 转 ASS 等确定性格式转换错误。

## 重试次数与等待

“最多三次自动尝试”包含第一次请求：

```text
第 1 次请求失败
→ 等待后进行第 2 次请求
→ 再次失败，增加等待后进行第 3 次请求
→ 第 3 次仍失败，返回最终错误
```

沿用现有递增等待和少量随机抖动，不新增无限重试。若服务商返回 `Retry-After`，继续以服务商要求的等待时间为下限。

## 与 RPM、Token 和 checkpoint 的关系

- 每次重试都会重新进入 `translateSubtitleChunk`，并在发起 API 请求前调用现有 `requestRateLimiter.waitForSlot()`。
- 重试会消耗新的 API 请求；如果服务商在空流前已经计算了 Token，也可能产生少量额外费用。
- 只重试当前失败的翻译窗口，不重新执行已经完成并写入 checkpoint 的字幕批次。
- 当前批次成功后继续按现有流程保存 checkpoint。
- 三次均失败时保留最后有效 checkpoint，用户仍可手动继续任务。

## 错误信息去重

当前错误收集会同时读取外层 `error.message` 与内部 `cause.message`，然后使用 ` | ` 拼接。若两条信息只有首尾空白、换行或连续空格的差异，界面可能显示两次看起来完全相同的错误。

修改后应在去重前：

1. 去除首尾空白；
2. 将连续空白规范化为单个空格；
3. 按规范化后的文本去重；
4. 保留第一条可读信息的内容顺序。

结构化 SSA 转 ASS 错误仍保持现有优先级，不被普通文本规范化破坏。

## 实现边界

建议将重试判断、错误信息提取和通用重试循环从体量较大的 `electron/main/index.ts` 提取到独立工具模块。主进程继续传入实际翻译函数、当前输入、延迟和取消信号。

该模块不负责：

- 自行调用翻译 API；
- 管理 RPM；
- 修改 checkpoint；
- 决定字幕批次；
- 改变并发任务数量。

这样能够用纯单元测试验证三次尝试、立即失败、取消和错误去重，而不需要启动完整 Electron 主进程。

## 测试要求

### 单元测试

- `NoOutputGeneratedError` 前两次失败、第三次成功时，总调用次数为三次并返回成功。
- 连续三次 `NoOutputGeneratedError` 时，第三次后抛出最终错误。
- HTTP 401 等不可重试错误只调用一次。
- 用户取消时不继续重试。
- 相同外层和内部错误即使空白不同也只显示一次。
- 两条真正不同的错误仍使用 ` | ` 保留。
- 现有 429、5xx、网络错误和 `NoObjectGeneratedError` 行为不回归。

### Electron 集成测试

- 模拟 API 前两次返回无有效输出、第三次返回正常译文，任务最终完成。
- 断言流式翻译请求总数为三次。
- 断言三次请求均经过同一个 API 账户 RPM 限制器。
- 模拟三次空流后任务才进入失败状态，checkpoint 保留。
- 模拟 401 时只发送一次请求。

### 完整回归

运行全部 TypeScript、单元、集成和 Electron E2E 测试，并确认 checkpoint、字幕编码、双重身份校验、SSA 转 ASS、并行 RPM、赞助提示和窗口生命周期不受影响。最后生成 Windows 构建并使用当前工作区新 EXE 做隔离 GUI 冒烟测试。

## 验收标准

- 偶发空流不会在第一次失败时停止任务。
- 第三次尝试成功时任务正常完成，不要求用户手动点击重试。
- 三次全部失败时才显示最终错误。
- 不可重试错误不会浪费额外请求。
- 重试不会绕过 RPM，也不会重译已经完成的字幕批次。
- 错误提示不再重复显示相同内容。
