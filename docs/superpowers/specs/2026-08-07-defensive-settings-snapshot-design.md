# 防御性设置快照设计

## 背景

Subtitle Translator 的界面语言、API 配置和翻译偏好主要通过
Chromium `localStorage` 分散保存。正常覆盖安装会继续使用同一个
Electron 用户数据目录，因此 2.1.3 到 2.1.5 的隔离升级测试能够继承
语言、API 配置和 RPM。

现有实现仍有一个薄弱点：每个设置只保留一个主值。只要某个键意外
缺失、格式损坏、被旧版本重复序列化，或者无法通过当前代码的严格
解析，该设置就会回退到默认值，而同一存储中的其他设置仍然正常。
这会形成“只有部分设置被重置”的现象。

## 目标

- 对所有现有、能够安全恢复的持久化设置建立版本化快照。
- 当前有效设置始终优先，旧快照不能覆盖用户的新选择。
- 单个设置缺失或损坏时，只恢复该项，不影响其他设置。
- 兼容普通字符串、标准 JSON 和最多两层重复 JSON 序列化。
- API 密钥与其他设置一样纳入保护，但仍只保存在应用现有的本机
  `localStorage` 中，不创建额外设置文件、不上传网络、不写入日志。
- 用户主动执行“重置全部设置”时，主设置、快照和损坏记录全部清除。
- 不改变安装器、Electron 用户数据目录、任务 checkpoint 或字幕文件。

## 非目标

- 不保证在整个 Chromium 用户数据目录被用户删除、磁盘损坏或系统清理
  后恢复设置。主值与快照位于同一个应用存储中。
- 不把设置同步到云端或不同电脑。
- 不引入新的密钥加密、账户系统或设置导入导出功能。
- 不恢复已经被用户主动重置的设置。

## 受保护设置

第一版设置注册表包含以下键：

| 键 | 内容 | 规范化规则 |
| --- | --- | --- |
| `language` | 界面语言 | `en-US`、`zh-CN`、`zh-TW` |
| `api_keys` | API 密钥列表 | 字符串数组，允许空字符串 |
| `api_host` | API 地址 | 字符串 |
| `api_provider` | API 服务商 | 现有四种服务商值 |
| `model` | 模型 | 字符串 |
| `ai_temperature` | 温度 | 有限数字，限制到 `0–2` |
| `delay` | 请求间隔 | 有限数字，最小为 `0` |
| `requests_per_minute` | RPM | 安全整数，限制到 `1–100000` |
| `translation_concurrency` | 翻译并发数 | 必须属于现有并发选项 |
| `prompt` | 翻译提示词 | 字符串 |
| `translate_lang` | 默认目标语言 | 字符串 |
| `translate_additional` | 默认附加要求 | 字符串 |
| `translate_context_size` | 上下文数 | 整数，限制到 `0–100` |
| `subtitle_output_format` | 字幕输出模式 | 必须属于现有输出格式 |
| `ass_translation_font` | ASS 译文字体 | 字符串 |
| `ass_original_font` | ASS 原文字体 | 字符串 |
| `translate_output_directory` | 输出目录 | 字符串 |
| `translation_success_count` | 成功翻译计数 | 非负安全整数 |

新增持久化设置时，必须同时加入注册表及对应测试，避免出现未受保护的
新设置。

## 存储结构

新增两个内部键，它们不对 UI 暴露：

```ts
const SETTINGS_SNAPSHOT_KEY = "settings_snapshot_v1";
const SETTINGS_QUARANTINE_KEY = "settings_quarantine_v1";
```

快照使用以下结构：

```ts
interface SettingsSnapshotV1 {
  version: 1;
  updatedAt: string;
  values: Partial<Record<SettingKey, string>>;
}
```

`values` 保存每项设置的规范 JSON 字符串，例如语言保存为
`"\"zh-CN\""`，RPM 保存为 `"60"`。API 密钥保存为 JSON 数组字符串，
但不得打印到控制台、错误消息、测试报告或遥测中。

损坏记录使用以下结构：

```ts
interface SettingsQuarantineV1 {
  version: 1;
  updatedAt: string;
  values: Partial<Record<SettingKey, string>>;
}
```

每个键最多保留最近一个无法恢复的原始值。该记录只用于避免启动修复
过程中永久丢弃原始内容；程序不会自动重新应用隔离值。

## 解析与规范化

新增纯函数设置模块 `src/utils/settings-storage.ts`。每个设置在注册表中
定义默认值、解析器和规范化器。

读取一个原始字符串时按以下顺序尝试：

1. 对原始字符串执行一次 `JSON.parse`，验证结果。
2. 如果解析结果仍是字符串，再执行第二次 `JSON.parse`，验证结果。
3. 如果第一次解析失败，把原始内容作为旧版普通字符串验证。
4. 最多解析两层，防止递归或异常超大输入。

成功解析后统一用 `JSON.stringify` 生成规范值。数值按当前 UI 已有边界
进行规范化；无效枚举、对象类型错误和无法解释的值判定为损坏。

## 启动恢复流程

`src/main.tsx` 必须在读取初始语言及渲染 React 前执行设置恢复：

1. 读取并验证 `settings_snapshot_v1`。
2. 按注册表逐项检查主设置。
3. 主设置有效：
   - 使用主设置；
   - 必要时把旧格式改写为规范 JSON；
   - 用该值刷新快照。
4. 主设置缺失或损坏，快照值有效：
   - 从快照恢复主设置；
   - 不修改其他有效设置。
5. 主设置损坏且快照也不能恢复：
   - 把原始值移入 `settings_quarantine_v1`；
   - 删除损坏的主键，使现有 Hook 使用默认值；
   - 不把默认值伪装成用户设置写入快照。
6. 主设置缺失且快照也没有该项：
   - 保持缺失，由现有 Hook 使用默认值；
   - 不创建无意义的默认快照项。
7. 将本轮确认有效的值写回版本化快照。
8. 使用恢复后的 `language` 启动 Lingui 和原生菜单同步。

恢复过程按键隔离。任何一个键发生异常都不得阻止应用启动或影响其他
键。

## 运行时快照更新

初始化完成后监听：

- `usehooks-ts` 发出的 `local-storage` 自定义事件；
- 浏览器原生 `storage` 事件；
- 页面退出前的 `pagehide` 事件。

发生设置变化时，在当前事件结束后的微任务中重新读取注册表中的主值：

- 先读取现有有效快照，再把能够成功解析的当前值合并进去；
- 当前有效值覆盖该键的旧快照；
- 当前值缺失或损坏时保留该键最后一个有效快照，防止一次异常删除或
  写坏同时破坏恢复副本；
- 不把损坏值、内部快照键或隔离键写回快照，也不因它们缺失而删除
  旧快照项；
- 多个连续事件合并为一次快照刷新。

快照刷新失败只记录不含设置值的通用警告，不影响用户继续使用软件。

## 主动重置

设置模块提供 `resetProtectedSettings(storage)`，先暂停运行时快照监听，
再调用 `storage.clear()`。现有“重置全部设置”改为调用该函数，然后重新
加载页面。因此主设置、快照和隔离记录会同时删除，`pagehide` 也不会在
页面退出前重新创建旧快照。重新加载后使用默认值，并从空状态开始建立
新的快照。

不得在 `clear()` 和页面重新加载之间执行恢复或快照刷新，否则会抵消
用户的重置意图。

## 错误与安全边界

- 不在任何日志中输出设置原始值、快照内容或 API 密钥。
- 解析单项失败时，只记录键名和错误类别。
- 快照本身损坏时，将其忽略并从当前有效主设置重建；不得因此清除主值。
- 快照版本未知时，不自动猜测结构；保留主设置并建立当前版本快照。
- 读写 `localStorage` 抛错时，应用继续使用现有默认行为。
- 不引入新的 IPC、外部文件、注册表项或网络请求。

## 测试方案

### 单元测试

新增 `tests/settings-storage.test.mts`，覆盖：

- 标准 JSON、普通字符串和双层序列化的兼容读取。
- 当前有效值优先于快照。
- 主值缺失时从快照恢复。
- 主值损坏时从快照恢复并按规范格式写回。
- 单项无法恢复时进入隔离区，其他设置保持不变。
- 损坏或未知版本快照不会清除当前有效设置。
- 数值范围、枚举、字符串数组和成功计数的规范化。
- API 密钥包含在快照中，但错误结果与日志不返回密钥内容。
- 主设置发生变化后，快照只更新对应的有效值。
- 运行时主键缺失或损坏后，`pagehide` 刷新仍保留该键最后一个有效
  快照。
- `resetProtectedSettings()` 会暂停监听、清除全部数据，并且不会在
  `pagehide` 时重建旧快照。

### Electron GUI 测试

扩展现有 E2E 测试，使用独立用户数据目录验证：

1. 保存中文、虚拟 API 密钥、API 地址、RPM、上下文数、模型、提示词、
   输出格式和输出目录。
2. 关闭并重新启动应用，确认所有设置保持。
3. 删除语言和上下文主键但保留快照，重新启动后确认两项被恢复。
4. 损坏一个数值键，确认该项从快照恢复且其他设置不受影响。
5. 修改快照为旧值但保留有效主值，确认当前主值不会被反向覆盖。
6. 点击“重置全部设置”，确认快照不会把设置恢复回来。

测试只使用虚拟密钥，不读取或复制用户真实数据。自动截图差异继续忽略，
不纳入提交。

## 兼容性与影响

- 2.1.3、2.1.4 和 2.1.5 现有的标准 JSON 设置可直接建立快照。
- 更早版本遗留的普通字符串和最多两层重复序列化值会迁移为规范 JSON。
- 现有 `useLocalStorage` Hook、设置 UI、安装器和用户数据目录保持不变。
- 首次启动新机制时会增加一个快照键，容量主要由提示词和 API 密钥决定，
  相对于 Chromium 用户数据可以忽略。
- 有效设置不会因为新增快照机制而改变；只有缺失或损坏的单项会触发恢复。
