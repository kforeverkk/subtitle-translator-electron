# Windows 工具栏应用图标设计

## 背景

主窗口顶部工具栏当前在左侧固定保留 `56px` 空间，用于避让 macOS
左上角的红黄绿窗口控制按钮。Windows 使用系统原生标题栏，窗口控制
按钮位于上一层标题栏右侧，因此这块空白没有实际用途，视觉上显得不
完整。

项目已经包含与用户提供图片一致的应用图标：

```text
src/assets/icon.png
```

本次直接复用该资源，不增加重复图片。

## 目标

- Windows 主窗口工具栏左侧显示应用图标，填补现有空白。
- macOS 保留现有 `56px` 避让空间，图标不得遮挡红黄绿窗口按钮。
- 不改变应用标题、右侧“新增任务”和“设置”按钮的位置。
- 不改变 About 窗口、系统原生标题栏或窗口控制行为。
- 图标只用于装饰，不增加点击、菜单或其他交互。

## 平台识别

在 Electron 预加载接口中增加只读平台字段：

```ts
platform: process.platform
```

对应渲染进程类型限制为：

```ts
"win32" | "darwin" | "linux"
```

界面使用该字段明确区分平台，不依赖已逐渐废弃的
`navigator.platform`，也不根据 User-Agent 猜测。

## 布局

顶部工具栏继续保持当前高度 `56px`。

### Windows

- 保留现有宽度为 `56px` 的左侧容器，避免标题和右侧按钮产生位移。
- 在容器中水平、垂直居中显示应用图标。
- 图片元素尺寸为 `40 × 40px`。
- 使用 `object-contain` 保持图标比例。
- 不额外添加边框、背景或阴影，因为图标图片本身已经包含圆角和阴影。
- 图片及其容器均为非交互元素，不阻断顶部工具栏的窗口拖拽。

### macOS

- 左侧继续显示空的 `56px` 避让容器。
- 不渲染应用图标，确保与 `trafficLightPosition` 配置不存在重叠。

### Linux

- 本次保持现状，继续显示空的 `56px` 容器。
- 该平台不属于本次用户提出的修复范围，避免未经实际截图验证便改变其
  布局。

## 边界和兼容性

- 仅修改渲染进程能够读取的平台信息和主工具栏左侧内容。
- 不开放 Node.js 能力，不新增 IPC，也不降低现有
  `contextIsolation`、`sandbox` 等安全设置。
- 平台字段只包含 Electron 已知的三个桌面平台值，不暴露路径或系统
  信息。
- 图标使用打包流程已经处理的 `src/assets/icon.png`，开发和安装版本
  使用同一资源。

## 测试与验收

### 自动测试

- 类型检查确认预加载对象和 `ElectronAPI` 声明一致。
- Electron E2E 在 Windows 上确认：
  - 工具栏应用图标存在；
  - 图标资源成功加载；
  - 图标显示尺寸为 `40 × 40px`；
  - 图标不是按钮或链接；
  - 标题和右侧操作按钮仍然可见。
- 现有完整单元测试和 Electron E2E 不得发生回归。

### 人工视觉验收

修改完成后构建并启动当前工作区的新版本，而不是电脑中已经安装的旧
版本。使用 Windows 实际 GUI 截取主界面预览图，先交由用户确认以下
内容：

- 图标大小是否合适；
- 图标与标题间距是否自然；
- 工具栏整体是否平衡；
- 右侧按钮及窗口系统按钮是否保持正常。

用户确认预览图后，再完成最终提交。
