# 跨任务输入字幕保护设计

## 目标

防止一个翻译任务的输出路径覆盖同一批次或其他同时运行批次正在使用的输入字幕。

目录中没有被任何活动任务选为输入的已有同名字幕仍可按现有规则覆盖。本次不改变普通输出与输出冲突的独占锁规则。

## 共享输入保护

输入路径采用共享只读登记：

- 多个任务可以同时登记并读取同一个输入字幕；
- 每个批次在任何异步翻译或文件写入开始前，登记该批次全部输入路径；
- 登记覆盖尚未进入并发池的后续文件；
- 不同批次对同一路径使用引用计数；
- 一个批次结束时只释放自己的登记，不影响其他仍在运行的批次。

输入路径登记与现有输出独占锁分离，不能把输入直接加入输出独占集合。

## 输出路径修正

输出身份完成新建或 checkpoint 复用后，检查最终输出路径是否属于任一活动输入路径。

如果冲突，按照已经确认的统一规则，在当前候选输出基本名后继续追加本次语言后缀：

```text
movie.en.srt
→ movie.en.en.srt

movie.en-zh.srt
→ movie.en-zh.en-zh.srt
```

如果追加后的名称仍属于另一个活动输入，则继续追加，最多尝试 100 次。达到上限后返回现有输出路径冲突错误，不进入翻译写入。

修正后的文件名写入 checkpoint 输出身份，后续续传保持稳定。已经安全且不与活动输入冲突的 checkpoint 输出身份保持不变。

## 跨批次时间顺序

如果输入路径先登记，后来任务计算出的输出会自动改名。

如果某个路径已经被正在运行的任务作为输出独占，之后的新批次又把它作为输入，则新输入任务不能安全启动，因为文件可能已经正在变化。该任务返回输出路径冲突错误，其他不冲突任务继续。

## 路径比较

沿用现有桌面路径语义：

- Windows 和 macOS 不区分大小写；
- Unicode 使用 NFC 规范化；
- 尽量使用真实目录路径统一符号链接目录；
- 不依赖目标输出文件是否已经存在。

## 现有输出冲突

本次不改变两个任务争用同一普通输出文件时的行为，仍由现有独占锁返回冲突错误。

输入保护导致两个任务最终落到同一个安全输出时，也由现有输出冲突机制处理；首要保证是不覆盖任何活动输入字幕。

## 不在范围内

- 为普通输出冲突自动编号或自动改名。
- 保护未被活动任务选为输入的目录文件。
- 修改翻译并发、API、RPM、Token 或 checkpoint 格式。
- 修改字幕内容、语言检测或输出格式。

## 验证

- 同一个输入同时翻译成多个语言仍允许。
- 同批后续输入在任务开始前受到保护。
- 输出撞到活动输入时重复追加语言后缀。
- 连续撞到多个输入时继续追加。
- 不同批次引用计数正确释放。
- 新输入撞到已经独占的活动输出时只让该任务失败。
- 修正后的输出身份能够 checkpoint 续传。
- 完整类型、单元、构建和 Electron E2E 回归。
