# 长字幕强制内容分析设计

## 目标

内容分析是长字幕翻译的一致性前置条件，而不是可选增强功能。字幕达到分析门槛时，只有完整、有效且已可靠保存的分析结果存在，翻译才能开始。

这样可以保证同一任务的所有字幕批次始终使用同一份内容梗概和术语表，避免分析失败后先无上下文翻译、续传时又启用上下文而形成前后风格不一致。

## 分析门槛

- 0～19条字幕：不进行内容分析，直接进入翻译。
- 20条及以上字幕：必须完成内容分析后才能翻译。

门槛按原字幕 cue 总数计算，不按剩余未翻译 cue 数计算。续传任务即使只剩少量 cue，只要原字幕总数达到20条，仍必须具有可复用的分析结果。

## 分析成功条件

内容分析结果必须同时包含：

1. 非空且结构有效的内容梗概 `plotSummary`；
2. 字段存在且结构有效的术语表 `glossary`。

`glossary` 允许为空数组，表示模型判断当前字幕没有值得提取的术语。只要字段存在并通过结构校验，空数组仍然是有效分析结果。

以下情况均视为分析失败并进入重试：

- 缺少 `plotSummary`；
- `plotSummary` 为空或类型错误；
- 缺少 `glossary`；
- `glossary` 不是数组；
- 术语条目缺少必要字段或字段类型错误；
- 模型返回普通文本或其他不符合结构化输出要求的内容；
- 模型未正常结束、返回空输出、API 临时错误或其他现有可重试错误。

## 重试和失败行为

长字幕内容分析使用项目现有的统一重试机制：

- 第一次失败后自动重试；
- 第二次失败后自动重试；
- 第三次失败后任务进入失败状态；
- 不进行第四次自动尝试。

三次均失败时：

- 不开始任何字幕翻译请求；
- 不生成新的部分译文；
- 不以“无分析模式”继续；
- 保留可恢复的 checkpoint；
- 用户手动重试任务时，可以再次执行最多三次内容分析。

错误信息应保留原始分析失败原因，便于区分 API、结构化输出、权限和网络问题。

## 分析结果的持久化顺序

分析成功后必须遵循以下顺序：

1. 将格式化后的内容梗概和术语表保存到 checkpoint；
2. 等待 checkpoint 原子写入成功；
3. 只有写入成功后才允许开始第一个字幕翻译请求。

如果分析成功但 checkpoint 无法保存：

- 任务直接失败；
- 不开始翻译；
- 继续显示现有 checkpoint 保存警告；
- 同时返回明确的“必要分析结果无法保存”错误。

这样软件重启后不会出现“已有部分译文，但无法证明它们使用了哪份分析结果”的状态。

## 相同配置续传

翻译配置指纹完全一致，并且 checkpoint 中存在有效分析结果时：

- 直接复用 checkpoint 中原有分析；
- 不重新调用内容分析接口；
- 所有剩余字幕继续使用同一份 `[Context]`；
- 保留已有译文和翻译进度。

这里以现有翻译配置指纹为准，而不是只比较 `taskId`。配置指纹覆盖：

- API 地址；
- 模型；
- 系统提示词；
- 目标语言；
- 附加提示；
- 温度；
- 上下文大小；
- 翻译管线版本。

## 配置变化

任一影响翻译内容的配置变化时，继续沿用现有重新翻译机制：

1. 旧 checkpoint 先被安全保留；
2. 清除全部旧译文；
3. 清除旧内容分析；
4. 使用新配置重新分析；
5. 分析成功并可靠保存后，从头翻译。

旧分析结果不能跨配置复用，因为目标语言、模型或提示词变化可能改变内容梗概语言和术语推荐译法。

## 旧 checkpoint 兼容

旧版 checkpoint 可能已经包含部分译文，却没有内容分析结果。对于总 cue 数达到20条的任务：

- 不允许直接沿用这些旧译文继续翻译；
- 将旧 checkpoint 按现有备份所有权规则安全保留；
- 清除活动任务中的旧译文；
- 重新执行内容分析；
- 分析成功并可靠保存后，从头翻译；
- 新任务成功完成后，按现有规则清理该任务拥有的 checkpoint 和备份。

旧 checkpoint 没有分析、也没有任何已完成译文时，可以直接执行内容分析，不需要为了空进度额外备份。

旧 checkpoint 已经包含有效分析结果时，继续按照相同配置续传规则复用。

## 短字幕行为

少于20条 cue 的字幕：

- 不要求 `analysis` 字段；
- 不调用内容分析接口；
- 不因为旧 checkpoint 缺少分析而重新开始；
- 继续使用现有字幕翻译、checkpoint 和续传流程。

## checkpoint 数据兼容

继续使用现有 `analysis?: string` 字段保存经过结构校验并格式化后的内容梗概和术语表。无需仅为本次行为修改而升级 checkpoint 版本。

有效分析字符串由现有格式化函数生成，必须始终显式包含内容梗概段和术语表段。旧 checkpoint 中已有的非空分析字符串继续视为可复用分析结果。

## 错误处理

新增或复用结构化错误码，至少区分：

- 内容分析三次失败；
- 分析结果结构不完整；
- 分析成功但必要 checkpoint 保存失败；
- 用户取消任务。

取消任务不应被转化为普通分析失败，也不应继续重试或开始翻译。

## 测试

### 单元测试

- 19条字幕不需要分析。
- 20条字幕需要分析。
- 已有分析结果时不重复分析。
- 内容梗概和术语表缺一时拒绝结果。
- 空术语表数组可以通过。
- 术语表条目结构错误时拒绝结果。
- 分析失败时最多执行三次，不开始翻译。
- 配置变化时旧分析被清除。
- 旧长字幕 checkpoint 有部分译文但无分析时触发重新开始。
- 旧短字幕 checkpoint 缺少分析时仍正常续传。

### Electron E2E

1. 20条字幕的分析连续失败三次，验证任务报错、翻译请求数为零、没有部分输出。
2. 分析成功后翻译中途失败，重新启动应用续传，验证不再请求分析并复用相同分析内容。
3. 修改模型、提示词或目标语言后重试，验证旧分析和旧译文不被复用，重新执行分析。
4. 构造旧长字幕 checkpoint：已有部分译文但无分析，验证旧进度被安全备份，重新分析并从头翻译。
5. 分析成功但 checkpoint 写入失败，验证翻译请求数为零并显示明确错误。

## 非目标

- 不要求少于20条的字幕进行内容分析。
- 不要求术语表至少包含一条记录。
- 不在分析失败后自动切换到无分析翻译。
- 不在续传时重新生成已有且配置匹配的分析结果。
- 不改变现有内容分析的抽样预算和抽样分布算法。
